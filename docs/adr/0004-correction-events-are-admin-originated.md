# Correction Events Are Admin-Originated

Ordinary protocol Form Submissions may create Provisional Study Events in the offline field app so field work can continue. Correction/Revisit Form Submissions do not create Correction Events offline; they remain linked to their Issue until backend/admin review.

Correction Events are originated only by the backend/admin workflow after Central Data Manager approval. This preserves the authority boundary between offline data collection and centrally approved correction of projected state and workflow.

Verified member/BWQ workflow corrections are a narrowly authorized online exception: Central Admin or an own-site Site Data Manager/Research Scientist may preview, verify and apply audited corrections from the configured field registry, with affected-task reconciliation. See the current admin-corrections policy. General proposal/approval boundaries and completed clinical history remain protected.
